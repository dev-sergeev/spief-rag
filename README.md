# RAG по стенограммам ПМЭФ

[demo.ipynb](demo.ipynb) — разбор проекта: данные, поиск, ответ, проверка и оптимизация.
Основной код находится в `.py`; ссылки на него есть рядом с примерами.

## Запуск

Python 3.13.5. Все команды выполняются из этой папки — корня самостоятельного проекта:

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

Укажите `CLOUD_RU_API_KEY` в созданном `.env`, затем запустите:

```bash
.venv/bin/jupyter lab demo.ipynb
```

Выполняйте ячейки сверху вниз. Ключ загружается в первой ячейке; ответы, оценки и сравнение рассчитываются заново.

Для выполнения без интерфейса с сохранением свежих выводов в ноутбук:

```bash
.venv/bin/jupyter nbconvert --to notebook --execute --inplace demo.ipynb --ExecutePreprocessor.timeout=3600
```

Эта команда также вызывает API; лимит 3600 секунд задан на одну ячейку, не на отдельный запрос.

## Структура

- `demo.ipynb` — точка входа и пошаговая демонстрация.
- `*.py` — загрузка данных, поиск, ассистент, оценка и эксперименты.
- `data/` — стенограммы, golden-набор, рубрика и контрольные примеры судьи.
- `results/` — сохранённые отчёты запусков.
- `requirements.txt`, `.python-version` — зависимости и версия Python.
- `.env.example` — шаблон настройки ключа; настоящий `.env` остаётся локальным.

`.gitignore` исключает ключи, `.venv/`, `.local/`, кэши Python и контрольные копии Jupyter.
Данные и отчёты не исключены. Имя корневой папки произвольное; вложенная `project/` не нужна.

## API и данные

Ключ `CLOUD_RU_API_KEY` хранится в `.env` рядом с `demo.ipynb`; пример — [.env.example](.env.example).
Можно передать ключ через переменную окружения: она имеет приоритет над `.env`.
Файл читает `python-dotenv`, он не исполняется как Bash-код. Родительские и соседние папки не используются.

`Run All` вызывает API: один пример, baseline на 15 вопросах, оценка судьёй, девять экспериментов и демонстрация выбранной стратегии на новых запросах.
Полный прогон может занимать десятки минут; самый долгий этап — сравнение девяти алгоритмов.
Генерация: `GigaChat/GigaChat-3-Pro`, эмбеддинги: `ai-sage/Giga-Embeddings-instruct-3B`, судья: `deepseek-ai/DeepSeek-V4.1-Flash`.
Адрес API: `https://foundation-models.api.cloud.ru/v1`.

Судья использует JSON Output (`json_object`), получает схему `Verdict` в системном промпте
и работает с `thinking=disabled`. Ответ строго проверяется Pydantic; повторов и исправления JSON нет.
Параметры формата и thinking записываются в метаданные оценки.

Модель выбрана по [каталогу Cloud.ru](https://cloud.ru/products/evolution-ai-factory/catalog-foundation-models).
Последнее опубликованное обновление DeepSeek V4.1 Flash — [1017 от 17.10.2026](https://api-docs.deepseek.com/updates/);
Cloud.ru не указывает точную ревизию за своим идентификатором.
Формат запроса соответствует [документации DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode).

Только эмбеддинги текстов и вопросов кэшируются в `.local/embeddings-giga-3b.sqlite`.
При отсутствии кэша первый запуск отправит корпус на индексацию и займёт больше времени.

## Результаты

Каждый запуск создаёт новые отчёты в `results/`: ответы, вызовы инструментов, оценки и фактические токены.
Старые отчёты не подставляются вместо запросов API. Сравнение использует только результаты текущего запуска.
Если ни один вариант не экономит токены без снижения качества, ноутбук оставляет baseline.
В сравнении участвуют пять оптимизаций контекста/промпта, Self-consistency, Tree-of-Thought,
принудительный поиск и планирование с исполнением. Единственный `comparison.selected`
выбирается среди всех алгоритмов; таблица показывает экономию, качество и причины отказа.
`load_selected_strategy()` повторно проверяет отчёты и возвращает конфигурацию вместе
со способом исполнения. `run_demo(..., execution=...)` запускает именно этот способ:
при `forced` оба поиска выполняет Python до единственного вызова LLM, без function calling.
Сохранённые ранее отчёты и выводы ноутбука могут относиться к прежней модели судьи.
Для сравнения с новым судьёй выполните ноутбук заново: baseline и все варианты должны оцениваться одной моделью.

Для скринкаста пройдите ноутбук сверху вниз: поиск, ответ, оценка, сравнение и свой вопрос.
